## 精度验证

 精度验证前，务必使用`patch/baseline-bug-fixed.patch`修复官方llama.cpp（commit `3ac67535c86`）的基线问题。

 步骤如下。

 1. 将源码切换到官方llama.cpp（commit `3ac67535c86`）对应的版本。
 2. 执行`git apply baseline-bug-fixed.patch`修复基线问题。
 3. 编译该版本并用于精度验证。

 ```shell
 python eval_llamacpp_cmteb.py \
--servers baseline=http://<ip>:<port> opt=<ip>:<port> \
--server-workers 2 \
--task-names   TNews IFlyTek MultilingualSentiment JDReview OnlineShopping Waimai     CLSClusteringS2S.v2 CLSClusteringP2P.v2 ThuNewsClusteringS2S.v2 ThuNewsClusteringP2P.v2     Ocnli Cmnli     T2Reranking MMarcoReranking CMedQAv1-reranking CMedQAv2-reranking     ATEC BQ LCQMC PAWSX STSB AFQMC QBQTC   \
--cmteb-root /path/to/C-MTEB \
--batch-size 1 \
--max-chars 500 \
--skip-bad-embedding \
--output-dir ./f16-all \
--continue-on-error
 ```

>![表示说明的图片](./public_sys-resources/icon-note.gif)**说明:**
>
>- servers后面以`<server_name>=<server url>`设置llama server，使用空格分离多个server。
>- server-workers数量等于上面的server数量，测试几个server就用几个worker。
>- cmteb-root改成自己的C-MTEB数据集路径。
>- 如果Task的分数是NaN，可以再运行该Task。

## 性能验证

### 单核验证

```shell
taskset -c 128 env  GGML_FUSED_CPP_SDPA=1 GGML_TOTAL_THREADS=1 OMP_NUM_THREADS=1 ./build-delivery/bin/llama-bench -m /path/to/bge-m3-FP16.gguf -p 512 -b 512 -n 0 -t 1 -r 1
```

#### 参数说明

|参数|说明|
|--|--|
|GGML_FUSED_CPP_SDPA=1|启用SDPA特性|
|GGML_TOTAL_THREADS=1|单线程|
|OMP_NUM_THREADS=1|OMP单线程|
|m|模型路径|
|p|设置Prompt Processing（预填充）阶段的输入长度为512个tokens。|
|b|逻辑批次大小（Batch Size）为512，在纯CPU推理且输入为512的情况下，这通常意味着将 512个tokens作为一个完整的批次进行处理。|
|n|设置生成的token数量为0。这意味着完全跳过Text Generation（解码）阶段，只测试 Prefill阶段的吞吐量。|
|t|设置llama-bench自身的工作线程数为1。|
|r|设置每个测试的重复次数为1次。|

### 整机验证

```shell
vim bench_bgem3_full.py   
python bench_bgem3_full.py   
```
